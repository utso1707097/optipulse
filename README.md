# OptiPulse

**A high-performance feature-flagging platform, A/B testing evaluation engine, and AI-driven micro-copy variant generator.**

OptiPulse delivers deterministic, sub-5-millisecond flag decisions at scale, instant global
kill-switches, weighted A/B/n experiments, and on-brand micro-copy variants generated by an AI
gateway behind a human-approval gate — governed by an immutable audit trail.

> **Status:** Specification & planning complete (spec-driven). Implementation in progress.
> This repository is being built with [Spec Kit](https://github.com/github/spec-kit) — the source
> of truth for *what* and *how* lives under [`specs/`](specs/) and
> [`.specify/memory/constitution.md`](.specify/memory/constitution.md).

---

## What it does

| Capability (bounded context) | Summary |
|------------------------------|---------|
| **Evaluation Engine** | Deterministic, zero-allocation in-memory flag evaluation (MurmurHash3 bucketing), p99 < 5 ms, fail-safe to last-known-good during outages. |
| **Flag Management** | Author flags, targeting rules, percentage rollouts, and A/B/n experiments; emergency kill-switch propagates to all nodes in < 100 ms. |
| **AI Gateway** | Generate micro-copy variants via a swappable AI provider; nothing reaches users without recorded human approval. |
| **Audit & Telemetry** | Immutable, attributable record of every change + per-variant exposure telemetry for winner analysis. |
| **Identity & Access** | Custom JWT authentication with role-based access control (Manager vs Admin/DevOps), enforced entirely in the backend. |

## Clients

- **Web Dashboard (React)** — always-online console for Product & Marketing managers: flag creation,
  experiment management, micro-copy generation/approval, analytics. Lightweight custom hooks, no Redux.
- **Mobile App (Flutter)** — offline-first ops app for Admin & DevOps engineers: real-time telemetry,
  push notifications on critical events, instant kill-switch. iOS + Android (Clean Architecture, BLoC/Cubit).

## Architecture at a glance

- **Backend:** .NET 10 Web API, Clean Architecture across four DDD bounded contexts + an Identity &
  Access subdomain, Native AOT–compatible, zero-allocation evaluation hot path.
- **Data & messaging:** EF Core 10 (SQLite dev / PostgreSQL prod, per-context `DbContext`), Redis
  Pub/Sub for < 100 ms cache invalidation, Polly resilience with fail-safe fallback.
- **Contracts:** Native OpenAPI spec is the single source of truth; TypeScript (React) and Dart
  (Flutter) clients are generated from it, with a CI drift gate preventing contract divergence.

## Engineering principles (constitution v2.1.0)

1. **Clean Architecture & Layer Discipline** — inward-only dependencies across all stacks.
2. **Zero-Allocation Performance** *(non-negotiable)* — < 5 ms, zero steady-state allocations, benchmark-gated.
3. **.NET 10 Modern Standards** *(non-negotiable)* — Native AOT compatible, warnings-as-errors.
4. **Resilience & Fail-Safe Kill-Switch** — Polly everywhere; kill-switch fails safe to "off".
5. **Dual-Client Strategy** — always-online React + offline-first Flutter, each fit for purpose.
6. **Backend-Contained Auth** — custom JWT/RBAC; clients hold no auth logic or secrets.
7. **Contract-First API Security** — native OpenAPI, CI fails on client contract drift.
